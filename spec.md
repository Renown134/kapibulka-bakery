# Спецификация «Капибулки»

## Назначение и интерфейс

Учебный сайт мини-пекарни. Существующий `index.html` остаётся интерфейсом и отдаётся сервером. Шапка «Капибулка», обещание «Тёплая булка для уютного дня», заметная карточка «Коричная капибара», меню круассанов, три коротких шага и учебная оговорка. Кремовый фон, тёмно-зелёная карточка, коралловые акценты; встроенная иллюстрация сохранена.

При открытии страница запрашивает меню. Три фиксированные позиции: «Коричная капибара», «Ванильный круассан», «Шоколадный круассан». Кнопка каждой позиции отправляет её id серверу; после успешного ответа видны подтверждение, выделение одной выбранной карточки и кнопка сброса. Кнопка выбранной позиции скрывается; можно выбрать другую позицию. Сброс через API снимает выделение, возвращает кнопки выбора и скрывает сброс, сообщая результат. Перезагрузка возвращает состояние без выбора.

Кнопка «Проверить пекарню» запрашивает серверное время и показывает его с локальным форматированием. Ошибки меню, выбора, сброса и статуса выводятся текстом; неуспешный запрос не меняет выбор. На время запроса выбора или сброса повторные нажатия блокируются.

## API

Все ответы API — JSON UTF-8 с `Cache-Control: no-store`. Маршруты читаются без строки запроса.

| Метод и маршрут | Ответ / поведение |
| --- | --- |
| GET `/`, GET `/index.html` | 200, существующий `index.html`, HTML UTF-8; 500 при ошибке чтения |
| GET `/api/menu` | 200: `{ "ok": true, "items": [{ "id": "cinnamon-capybara", "name": "Коричная капибара" }, { "id": "vanilla-croissant", "name": "Ванильный круассан" }, { "id": "chocolate-croissant", "name": "Шоколадный круассан" }] }` |
| POST `/api/selection` | JSON `{ "id": "cinnamon-capybara" }` с `Content-Type: application/json`; 200: `ok`, `item` с id и name, `message` с учебным подтверждением |
| POST `/api/reset` | 200: `ok: true`, `message` о сбросе; без сохранения состояния |
| GET `/api/status` | 200: `{ "ok": true, "time": "<текущее серверное время в ISO 8601 UTC>" }` |
| Остальные пути и методы | Явный 404 JSON: `ok: false`, сообщение об отсутствии маршрута |

Для выбора: 400 при невалидном JSON или неизвестном/отсутствующем id, 415 при неподходящем Content-Type, 413 при теле больше 8192 байт. Ошибки не отражают содержимое пользовательского ввода. Сброс не требует тела и не ищет ранее сохранённый выбор.

## Сервер и конфигурация

`package.json`: реальное `private: true`, scripts.start — `node server.js`, scripts.build — `node --check server.js`. Нет dependencies и devDependencies. `server.js` использует только `node:http`, `node:fs`, `node:path`; читает существующий HTML, ничего не записывает.

Адрес прослушивания — `0.0.0.0`. Порт — `process.env.PORT`, при отсутствии 3000; значение 0 допускается для проверки автоматически выделенного порта. Безопасная строка запуска выводится только в callback успешного listen, содержит адрес и фактический порт. При занятом или недопустимом порте процесс завершается с ошибкой без сообщения об успешном запуске.

`amvera.yaml`: meta.environment — node, toolchain.name — npm, toolchain.version — 18; build.additionalCommands — npm run build; run.command — npm run start; run.containerPort — 3000.

## Ограничения и готовность

Только восемь файлов в корне: AGENTS.md, README.md, PLAN.md, spec.md, index.html, package.json, server.js, amvera.yaml. AGENTS.md не изменяется. Новое разрешение пользователя на сервер, API и меню имеет приоритет над прежними ограничениями локальной страницы.

Нет внешних зависимостей, сборщиков, отдельных статических папок, Docker, Volume, Variables, команд Amvera CLI, БД, SQLite, файлов сохранения выбора, сессий и изменяемого серверного состояния. Фиксированное меню неизменно; серверный timestamp вычисляется при запросе. Нет хранилища браузера, внешних запросов, оплаты, настоящих заказов, авторизации, реальных данных или секретов. Функции за пределами согласованного сценария не добавляются.

Готовность наблюдаема: сборочная проверка проходит; обе HTML-ссылки возвращают интерфейс; меню показывает три позиции; выбор и сброс работают для каждой; статус возвращает текущее время; неизвестные маршруты и методы дают 404. Текст читается в узком и широком окне, кнопки работают с клавиатуры, фокус заметен, статусы доступны вспомогательным технологиям. Проверка в браузере и успешный деплой подтверждаются отдельно, их нельзя считать выполненными по одному лишь чтению кода.
